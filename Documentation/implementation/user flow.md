# User Flow

## Goals
- Capture the current CLI user flow from landing to all implemented paths.
- Highlight global commands available on every page.
- Suggest low-risk optimizations without changing behavior yet.

## Global CLI Behavior
- Input is case-insensitive and trimmed.
- A unique prefix of a command is accepted (shortest unique prefix).
- Invalid commands print `invalid command` and re-display options.
- `back` / `b` returns to the previous page (no-op at the root).
- `exit` terminates the application.

## Current Flow (Implemented)
### Landing Page
Prompt: "Are you a Game Master or a Player?"
- `dm` -> Campaign Selection
- `player` -> Player Mode (placeholder, intentionally kept for future work)

### Campaign Selection
- Lists existing custom campaigns (by folder name).
- `create` -> New Campaign
- `rename` -> Rename campaign
- `delete` -> Delete campaign
- Selecting a campaign name -> DM Menu (for that campaign)

### New Campaign
- `default` -> Create from default campaign template.
- `blank` -> Create blank campaign (same files, empty arrays).
- After creation -> DM Menu (new campaign selected).

### DM Menu (for selected campaign)
- `create` -> Placeholder page
- `edit` -> Placeholder page
- `delete` -> Placeholder page
- `open` -> Placeholder page

### Player Mode (Placeholder)
- Placeholder page (no implementation yet).

## Implemented Data/Storage Capabilities (Backend)
These are not wired to CLI yet, but exist and should be reflected in future flow extensions:
- CRUD repositories for:
  - Classes, races, items, spells, places
  - Effects, damage types, beasts, monsters, NPCs
  - Players
  - Languages, alchemy ingredients, books
- Campaign template creation for default/blank campaigns.
- Id registry stored in `world/id-registry.json` with a handler for add/remove/find.

## Proposed Extended Flow (Design-Only, Not Implemented Yet)
### DM Menu -> Create
- Choose entity type to create:
  - Class, Race, Item, Spell, Place
  - Effect, Damage Type
  - Beast, Monster, NPC
  - Language, Alchemy Ingredient, Book
  - Player
- Each creation path:
  - Prompts for required fields
  - Validates inputs (range, enums, ids)
  - Writes to the matching JSON catalog
  - Registers id in id-registry.json

### DM Menu -> Edit
- Choose entity type
- List entities by name/id
- Select entity to edit
- Update fields
- Save to catalog

### DM Menu -> Delete
- Choose entity type
- List entities
- Confirm deletion
- Remove from catalog
- Remove id from id-registry.json

### DM Menu -> Open
- Choose entity type
- List entities
- View full entity details

### Campaign Selection -> Rename
- Select campaign
- Enter new name
- Validate uniqueness
- Rename folder

### Campaign Selection -> Delete
- Select campaign
- Confirm deletion
- Remove campaign folder

## Optimization Suggestions
- Add a short help section on each page (commands + quick hints).
- Add `list` command where large catalogs are present to avoid auto-printing long lists.
- Add `search <text>` for long catalogs (spells/items/monsters).
- Add `confirm` step for destructive actions (delete) to reduce mistakes.
- Add a `recent` list of last opened campaigns to speed up selection.

## Decisions
- **Player mode** remains a visible placeholder until implemented.
- **Campaign rename/delete** should be supported from campaign selection.
- **Ids** are autogenerated by `IdHandler` from the entity name; users should not edit ids directly.
- **Deletion** requires a double confirmation; **renaming** does not.

## Open Questions
- Should ids be generated from a "base name" prompt or from the entity name automatically?
- Should rename/delete require a double confirmation (e.g., type campaign name)?
